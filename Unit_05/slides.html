Unit 05

Color Roles

不是選幾個好看的顏色，是給每個顏色一個工作

Material Design 3 用色彩角色（Color Role）取代「固定色票」——每個角色有明確用途，不是單純一組顏色。角色名稱前綴 On 的顏色，代表疊在對應角色「上面」的文字或圖示顏色，這個配對本身就是為了確保對比度足夠。

角色用途
Primary / On Primary主品牌色與其對比色，用在關鍵動作、高強調元素
Primary ContainerPrimary 的淺色版本，用在強調較低的元件，例如選取狀態
Secondary / Tertiary次要動作與第三強調色，做視覺平衡
Surface / On Surface卡片、選單的背景色，與疊在上面的文字

Roles In Practice

五個角色，套進五種畫面情境

每張卡片的色塊是角色本身，色塊上的文字用對應的 On 角色——這是實際套用時最容易漏掉的一步：只挑背景色，忘了同時決定疊在上面的文字色。

Unit 05

Choosing A Scheme

挑一個來源色，其他顏色讓工具算

Material 3 的做法：從單一來源色（source color／seed color）——通常是品牌色，用演算法自動生成一整套跟角色一一對應的色階，不用手動挑幾十種深淺。

① 挑來源色不要太飽和也不要太灰，中等飽和度效果最好
② 產生色階Primary／Secondary／Tertiary／Neutral／Error 各自的完整色階
③ 套進角色每個角色從對應色階裡取一個色階值，亮／暗兩種主題各一套

WCAG Contrast

顏色好看不等於看得清楚

色彩角色選好之後，還要過這道檢查——這不是美感問題，是視力約 20/40 的使用者能不能舒適閱讀的問題。

4.5:1一般文字（18pt 以下）
WCAG AA 最低門檻
3:1大字級文字（18pt 以上）
門檻較低，因為大字本身較好辨識
7:1WCAG AAA 一般文字
更高標準，非必要但值得追求
純裝飾用文字、Logo／商標文字不受這個門檻限制，但介面上其他所有文字都要過。

Type Scale

五組角色，管住整個產品的字級

Display（最大，短而重要的文字）→ Headline（區塊標題）→ Title（Card／對話框內的標題）→ Body（內文）→ Label（按鈕、標籤等最小的文字）。

Unit 05

Type Tokens

每個字級 Token，同時記錄四件事

屬性在調什麼
Font size文字的視覺大小
Line height確保可讀性的垂直間距
Font weight粗細與強調程度
Letter spacing調整字元密度的水平間距（Tracking）
套用時直接從 15 個 Token 裡挑對應角色使用，不用每個畫面各自決定字級——這是維持文字風格一致的關鍵。

Unit 05

Icon Principles

Icon 的空間很小，禁不起複雜

Icon 尺寸有限，每一個都要嚴格遵守準則，同時表達出概念最核心的特徵。

  • 簡化，讓概念容易理解，同時提高辨識度。
  • 避免複雜的設計。細節在小尺寸下會糊成一團。
  • 用幾何、粗體的形狀，不要用細緻、寫實的描繪。

Unit 05

Icon Sizing

標準是 24dp，另外三種各有情境

20dp 用在桌面、密集版面與小型視覺元素；40dp／48dp 搭配 Display／Headline 這類大字級與大螢幕。跟文字對齊時，Icon 基準線要下移約文字字級的 11.5%。

Unit 05

Button States

一顆按鈕，五種要各自設計的樣子

狀態代表意思視覺處理
Enabled已準備好被點擊高對比，清楚的標籤
Hover游標移到上面顏色些微加深或加陰影
Pressed正在點擊的瞬間顏色變化 + 輕微縮小，100–150ms 內要有回饋
Focus鍵盤 Tab 導覽到這裡清楚的外框，不能只靠顏色（無障礙硬性要求）
Disabled目前不可用降低對比，但文字仍要可讀

Unit 05

In Practice

五個狀態放在一起比，差異要看得出來

Focus 用外框而不是只改顏色；Disabled 降低對比但文字仍讀得出來——這兩點最容易被學生省略。

Button Labels

原則意思

Common Blockers

練習時最常卡住的四個地方

卡住的地方原因怎麼解
