Unit 11

Handoff

開發者不是流程最後才收到檔案的人

Figma 官方的說法很直接：把開發者當協作夥伴，不是最後一站的收件人。及早分享檔案、保持過程透明、讓對方看得到你的迭代，是設計師跟工程師互信的基礎——不是等你畫完才丟過去。

✕ 常見做法做完整份設計才丟連結，附一句「照這個做」
✓ 官方建議做法邀請開發者從一開始就用 Viewer 身分加入檔案，持續提問與給回饋

Unit 11

Before Handoff

丟連結之前，先把這幾件事做完

  • 用 Emoji 標頁面狀態。🏗️ 施工中／💭 待討論／🚢 可上線，一眼看出哪些定案了。
  • 最終設計做成 Component Instance，放在乾淨的頁面，跟散亂的工作區分開。
  • Component 完整記錄：名稱、說明、使用方式、Variant 都要寫清楚。
  • Style／Variable 命名跟程式碼庫慣例一致，不要自己另外一套。
  • 說明欄位加無障礙注意事項與相關連結，開發者不用另外問。

Dev Mode

切到開發者視角，按 Shift + D

Dev Mode 是「以開發者為中心的介面，用來檢視與瀏覽設計」。打開一份 Design 檔案後按 Shift + D 切換，同一個鍵可以切回來。

Ready for dev標記 Component、Frame 或 Section 已經準備好交給開發者實作
Completed（Org／Enterprise）多一個狀態可以追蹤已經做完的項目

Communication

紅線標註稿，換成有脈絡的說明

官方建議：不要只給傳統的紅線標註稿，改成分享問題定義、研究過程、迭代決策的敘事脈絡——工程師要知道「為什麼這樣設計」，不是只知道「這裡是 16px」。

① 邀請 Viewer免費、不需付費授權，讓對方能檢視、匯出、留言
② 附脈絡說明Code Panel 顯示 CSS／iOS／Android 片段搭配元件細節
③ 早期邀請設計還在進行時就讓開發者加入，持續問、持續回饋

Claude Code

活在終端機裡，會自己規劃工作的 Agent

Claude Code 是「一個活在終端機裡的 agentic 編碼工具」，官方特別強調：它不是生成程式碼的聊天介面，而是會規劃工作、讀你的檔案、跨多個目錄編輯、跑測試的 Agent。裝好之後，在專案資料夾裡打 claude 就能開始。

No-Code 實作
Unit 11

Figma MCP

讓 Claude Code 直接讀懂你的 Figma

Figma MCP Server 讓 Claude Code「讀取結構化的設計脈絡——Component、Variable、版面資料——並從選取的 Frame 產生程式碼」。連上之後，顏色、間距、Variant 可以直接從真的檔案讀取，不用你再把規格轉成文字講一次。

Setup

裝一次，之後每個專案都能用

步驟做法
1終端機執行 claude plugin install figma@claude-plugins-official
2按 Enter，重新啟動 Claude Code
3輸入 /plugin，切到 Installed 分頁
4選 figma 伺服器，按 Enter 授權登入
5跳出頁面點「Allow access」
6回終端機再打一次 /plugin，確認顯示已連線

Gemini CLI

同樣的邏輯，換一家做

Gemini CLI 是 Google 的開源 AI 終端機助手，一樣是用自然語言下指令、讀懂脈絡、直接改檔案的 REPL 環境，內建檔案操作、Shell 指令、網頁擷取，也支援 MCP 接上 Figma。清華大學課程大綱把兩者並列介紹——操作邏輯共通，上課示範用哪個看現場帳號能不能用決定。

Common Blockers

練習時最常卡住的幾個地方

卡住的地方原因怎麼解
/plugin 裡沒看到 figma沒有重新啟動 Claude Code，或授權頁面沒點 Allow access退出再重新啟動 Claude Code，重跑一次 /plugin，確認授權流程走完
生出來的網頁跟設計對不上選取的 Frame 範圍不對，或圖層命名太亂讓 AI 誤判結構選取式工作流程先確認選到正確的 Frame，圖層命名清楚一點有助 AI 辨識結構
不知道要跟 AI 說什麼指令太模糊，例如只說「做一個網頁」照兩種工作方式的範例句型講：先講要對哪個 Frame、要它做什麼

Communication Simulation

被問倒之前，先跟 AI 練一次
