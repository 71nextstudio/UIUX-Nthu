斷點設置策略

行動優先 vs 桌機優先

兩種截然不同的設計與開發思路，影響 Media Query 的寫法

🖥 Desktop First 桌機優先
製作順序：桌機 → 平板 → 手機　Media Query：max-width
📱 Mobile First 行動優先
製作順序：手機 → 平板 → 桌機　Media Query：min-width
真實情況：大多數團隊同時從兩端設計，選擇適合專案的那一個即可。Mobile First 的限制感能幫助做出更精準的決策。

概念比較

RWD 響應式 vs AWD 自適應

看起來相似，但背後的技術機制完全不同

比較維度 RWD 響應式設計 — 台灣高鐵 ↗ AWD 自適應設計 — 591 ↗
運作方式 同一套 CSS，依 viewport 流動調整 偵測裝置類型，載入對應版本
版面切換 平滑漸進，無跳動感 需要切換時間，可能有閃爍
維護成本 單一版本，維護簡單 多套版本，維護成本高
客製化程度 較難針對特定裝置大幅客製 可為每個裝置提供最佳化體驗
適用情境 大多數網站的首選方案 對效能要求極高的大型產品
現代主流：大部分網站採用 RWD，搭配 CSS Grid / Flexbox + Media Query，即可應對絕大多數的多裝置需求。
現場驗證：手機開 591 ↗，網址列會自己從 591.com.tw 變成 m.591.com.tw，分頁標題還寫著「591觸屏版」——這就是 AWD 的定義呈現在網址列上。對照組 台灣高鐵 ↗ 兩種裝置拿到的 HTML 一個 byte 都不差，是乾淨的 RWD。（2026/08 實測；網站會改版，上課前建議再開一次確認。）

核心概念 · Flow

流動性（Flow）

內容隨螢幕縮小而垂直堆疊，這稱為「流程（Flow）」

Flow（流動）
當螢幕變窄，下方的元素會被推下去，依序垂直排列。這是 CSS 的自然行為。
Static（靜態）
使用固定 px 定位時，元素不會流動，在小螢幕會超出邊界或重疊。
使用絕對像素（px）定位所有元素時，響應式設計容易出現排版問題。相對單位與流動排版 是 RWD 的基礎。

核心概念 · Units

相對單位與靜態單位

知道 % 和 px 各自的使用時機，是寫好 RWD 的基本功

相對單位（Relative Units）
%、vw、vh、em、rem
元素寬度隨螢幕或父元素縮放。50% 永遠佔螢幕一半。
靜態單位（Static Units）
px、pt
元素寬度固定，不隨螢幕改變。適用於不應縮放的元素，如 icon 大小、最小點擊區域。
最大最小值：width: 100%; max-width: 1200px — 內容填滿螢幕但不超過 1200px，是常見的版心寫法。

核心概念 · Breakpoints

斷點設計（Breakpoints）

何時切換行動版、何時切換桌機版——以及如何選擇最佳時機

With Breakpoints（有斷點）
在特定寬度（如 768px）觸發版面切換，每個斷點的體驗都是針對性優化的。
Without Breakpoints（無斷點）
使用 Flexbox Wrap 或流動網格，版面連續流動，無明顯切換點。
最佳斷點策略：斷點不應依照「iPhone 尺寸」來設定，而應在版面「開始看起來奇怪」的時候加斷點。讓內容決定斷點，而非裝置決定斷點。

核心概念 · Components

組件寫法（Nested Components）

善用容器包裝，讓響應式元件更容易控制與維護

Nested（嵌套容器）
用 wrapper container 包裝相關元素。容器設定 position: relative，子元素相對容器定位，不受整體版面影響。
適合用 px 的場合
Icon、按鈕最小點擊區域（44px）、邊框厚度等不應隨版面縮放的元素，適合使用靜態單位 px，讓它們保持固定大小。
適合用 % 的場合
版面欄位寬度、圖片最大寬度、全幅 banner 等需要隨螢幕縮放的元素，使用相對單位讓它們靈活流動。

字型與圖示選用

系統字型 vs 網頁字體 / 點陣圖 vs 向量圖

設計稿中兩個常被忽略但影響跨裝置顯示品質的細節

字型選用
🚫 System Fonts（系統字型）
系統字型僅在安裝該字型的裝置上顯示正確。Windows、Mac、iOS、Android 各有不同預設字型，跨平台呈現不一致。
✅ Web Fonts（網頁字體）
使用 Google Fonts 等 CDN 字型，所有裝置都會下載並呈現相同字型。注意行動網路的載入速度，控制字重數量。
圖示選用
🚫 點陣圖（Images / PNG / JPG）
解析度固定，放大後失真（模糊）。在 Retina 高密度螢幕上，icon 會顯得不清晰。
✅ SVG 向量圖（Vectors）
向量格式，任意縮放不失真。介面 icon、Logo 優先使用 SVG，檔案通常比 PNG 更小，且支援 CSS 動畫控制。

Figma 應用

在 Figma 設計多裝置版本

利用 Constraints 與 Auto Layout 讓設計稿反映響應式邏輯

Step 01
建立多個 Frame
分別建立 Mobile（375px）、Tablet（768px）、Desktop（1440px）三個 Frame，對應不同斷點。
Step 02
設定 Constraints
為每個元素設定 Left / Right / Scale 等 Constraints，使其在 Frame 縮放時保持相對位置關係。
Step 03
使用 Auto Layout
用 Auto Layout 建立流動元件，設定 Fill / Hug / Fixed 控制每個元素的縮放行為。
設計師的責任：在 Figma 中清楚標示「這個元件在手機版如何變化」，讓開發者能夠正確實作。Figma 的多 Frame 設計是與工程師溝通響應式邏輯的最佳媒介。
課堂練習：Figma 練習檔 ↗ 對應 Frame、Constraints 與 Auto Layout 這三個步驟。
