Exercise 01

挑一條路徑，拆成使用者的動作

15 分鐘個人練習檔 ① · 區塊 1

目標：先把「使用者實際會做什麼」講清楚，再開始畫圖。跳過這一步直接畫，通常畫到一半會發現步驟接不起來。

任務

  1. 打開 Unit 05 的 IA 圖，找出你標了顏色的核心路徑。挑一條，只挑一條。
  2. 寫下這條路徑的使用者目標，一句話。例如「下班通勤時，想接著看上次沒看完的課」。
  3. 把這條路徑拆成使用者實際的動作，一張便利貼一個動作，動詞開頭。
  4. 排出順序，先不用管分岔。

動作要怎麼寫

寫法例子問題
✗ 名詞「課程列表頁」這是畫面不是動作，看不出使用者在幹嘛
✗ 太籠統「使用 App」拆不出下一層，等於沒拆
✗ 系統視角「系統驗證使用者身分」使用者看不到這件事，先寫他看得到的
✓ 動詞開頭「點『我的課程』」「找到上次那堂」「按繼續播放」—
交件：一句使用者目標 + 5–10 張排好順序的動作便利貼。

Exercise 02

畫成 Flowchart，補上例外路徑

20 分鐘個人練習檔 ① · 區塊 2

目標：把線性的步驟變成有分岔的流程。這一步的重點不是畫得漂亮，是把例外找出來。

只要四個符號

符號代表寫法
◯起點／終點正式畫法是圓角矩形，畫成圓形也可以；一個起點，終點可以多個（成功、失敗、放棄）
▭動作或畫面動詞開頭
◇判斷點寫成是非題：「已登入？」
→路徑從菱形出去的每一條都要標條件
先看範例：Flow Chart 流程圖範例。「會員登入」那個含忘記密碼、驗證碼、密碼錯三次等分支，跟你等一下要補的例外路徑很像，可以照著看怎麼接。（那份多一個「資料輸出／輸入」的平行四邊形，你們用不到。）

參考格式

◯ 起點：從首頁點「我的課程」 │ ▼ ┌──────────────┐ │ 顯示課程列表 │ └──────────────┘ │ ▼ ◇ 有進行中的課程嗎？ │ ├── 有 ──▶ 顯示上次看到第幾分鐘 ──▶ 點「繼續看」──▶ ◯ 終點：開始播放 │ └── 沒有 ─▶ 空狀態：「還沒開始任何課程」＋ 去逛課程

例外路徑檢查表

理想路徑畫完之後，拿這六條逐一問自己。多數人第一次做會漏掉四條。

  • 沒資料：第一次使用的人打開這頁看到什麼？
  • 找不到：搜尋沒結果、篩選之後一個都不剩，怎麼辦？
  • 沒權限：沒登入、沒付費、帳號被停用，擋在哪一步？擋下來給什麼出路？
  • 出錯：網路斷掉、付款失敗、檔案太大？
  • 要等：需要載入三秒以上的地方，等待中顯示什麼？
  • 反悔：中途想退出、想改剛剛填的，回得去嗎？
自我檢查：看一下你畫的每個菱形。如果有哪個菱形只有一條線出去，那它就不該是菱形——要嘛改成矩形，要嘛去想清楚另一條路。
交件：一張含判斷點與至少 4 條例外路徑的 Flowchart。

Exercise 03

Auto Layout 練手：卡片與列表

20 分鐘個人練習檔 ② · Exercise 03

目標：在畫 Wireframe 之前先把工具練順。這 20 分鐘做出來的卡片，等一下畫畫面時直接複製來用。

Step 1 · 做一張卡片（8 分）

  1. 畫一個灰色方塊當縮圖（240 × 135），下面放標題文字、一行說明、一個標籤。
  2. 全選這四個，按 ⇧ A（Windows：Shift A）加上垂直 Auto Layout。
  3. 設定 padding 16、gap 8。
  4. 把卡片設成 Hug contents（雙擊 frame 邊緣）。
  5. 測試：把標題改成很長的一句話。卡片應該自己變高，下面的東西自己讓開。

Step 2 · 排成列表（7 分）

  1. 複製卡片三份，全選後加上水平 Auto Layout，gap 設 16。
  2. 外層設成 Fixed 寬度，例如 1200。
  3. 把每張卡片的水平尺寸改成 Fill container（⌥ + 雙擊）。
  4. 測試：把外層寬度改成 800。三張卡片應該一起變窄，間距不變。

Step 3 · 踩一次那個坑（5 分）

這一步是故意讓你踩的，踩過就不會忘。

  1. 把外層列表改成 Hug contents。
  2. 你會發現設不了，或者設了沒反應。
  3. 原因：裡面有子元件設成 Fill container，容器在那個軸向就會被強制變成 Fixed。
  4. 把卡片改回 Fixed 寬度，外層的 Hug 就正常了。
記住這條：Hug 只能給容器，Fill 只能給子元件；而且只要有一個子元件是 Fill，父容器那個軸向就自動變 Fixed。之後遇到「我明明設了 Hug 怎麼沒反應」，九成是這個。

看別人怎麼做

做完之後可以去 Wireframe Web UI Kit 挑一個卡片或列表區塊，拆開看它的 Auto Layout 是怎麼疊的：哪一層是容器、哪一層用 Hug、哪一層用 Fill。看別人的結構比自己硬想快很多。

Step 4 · 加上 min / max（有時間再做）

回家作業要做拉寬拉窄的壓力測試，會爆版的地方通常就是少了這兩個：

  • 文字容器加 max width：避免視窗拉很寬時，一行變成八十個字。
  • 卡片或區塊加 min height：避免內容很少的時候整塊塌掉。
交件：一張會自己撐開的卡片 + 一個會跟著容器縮放的列表。

Exercise 04

畫 3 個低保真 Wireframe

25 分鐘個人練習檔 ② · Exercise 04

目標：把流程圖上的節點變成畫面。挑頭、中、尾三個關鍵節點，不要平均分配。

挑哪三個

位置挑什麼例子
頭使用者進到這條流程看到的第一個畫面課程列表
中流程中最關鍵的判斷點所在的畫面課程詳情（決定要不要看）
尾任務完成的那個畫面，或最重要的一個例外狀態播放頁，或「還沒開始任何課程」的空狀態

畫到什麼程度

25 分鐘畫 3 張全部用 Auto Layout 做完是不切實際的。實際的做法是：

  • 第 1 張做完整：用 Auto Layout 排好，直接用 Exercise 03 的卡片。
  • 第 2、3 張先排骨架：方塊擺對位置、順序對就好，Auto Layout 留到回家補。
  • 如果某個畫面只有一小塊變動（例如篩選之後只有列表更新），只畫那一塊就好，不用整頁重畫一次。

可以用現成的 Wireframe 元件

不用每個方塊都自己畫。Wireframe Web UI Kit 裡有大量現成區塊——導覽列、Hero、卡片列表、表單、頁尾都有，桌機（1440）與手機（375）兩種尺寸，命名方式是「類型＿編號＿寬度」，例如 Header_3_1440、Hero_10_375。

可以怎麼用做法
✓ 當零件來源找到接近的區塊，複製到你的畫框，再依你的內容改文字與增減欄位。
✓ 當參考卡住的時候翻一翻「這種頁面通常有哪些區塊」，看完關掉，回來畫自己的。
✓ 當 Auto Layout 範例拆開別人做好的區塊，看它的容器怎麼疊、哪一層用 Hug 哪一層用 Fill。
✗ 直接拼一頁交差拖三個區塊湊成一頁，跟你的 Flow 沒有關係——這樣等於跳過這堂課要練的東西。
順序不能反過來。先看你的流程圖決定這一頁要放什麼，再去 Kit 裡面找對應的區塊；不是先看 Kit 有什麼，再回頭決定頁面長怎樣。判斷方式很簡單：如果你選某個區塊的理由是「它看起來不錯」而不是「我的流程需要這個東西」，那就是反過來了。

Kit 裡的區塊多半比低保真再精緻一點。複製過來之後把顏色拿掉、圖片換成灰方塊加一個叉，維持黑白灰。

畫的規則

  • 只能用黑白灰，要標重點就用一個藍色。
  • 文字用真的。寫「加入購物車」不要寫「按鈕」；寫真實的課程名稱不要寫 Lorem ipsum。假字排起來永遠很整齊，真字才知道會不會爆版。
  • 照片用灰方塊加一個叉代替，圖示畫個圈標「icon」。
  • 每一頁只能有一個最明顯的主要動作。
  • 全部用 Auto Layout 做，用 Exercise 03 的卡片直接複製。

畫完每一張，問這六題

  • 第一眼會看到什麼？那是這頁最重要的東西嗎？
  • 這一頁的主要動作是哪一個？它有比別的按鈕明顯嗎？
  • 使用者從哪裡來的？他知道自己在哪一層嗎？
  • 如果這裡沒有資料，畫面長什麼樣？
  • 按下去之後會發生什麼？成功跟失敗分別看到什麼？
  • 想回上一步的話，回得去嗎？
答不出來的那一題，通常是流程圖上漏掉的那條線。回去補流程圖，不要在畫面上硬掰。
交件：3 個低保真 Wireframe，每張旁邊寫下六題的答案。
成果分享（另計 15 分鐘）：抽點 3–4 位，每人 3 分鐘，只講三件事——你的使用者目標、流程上最難決定的那個判斷點、以及你補了哪些例外路徑。
回家作業 · 作業 5（上半）

把流程補完，畫面補到 5 張

個人作業。作業 5「Flowchart + UI Flow + Wireframe」是 Unit 06 跟 07 合起來完成的，這次先交流程與初版畫面，Unit 07 再細修並合成 Wireflow。

Homework

完整流程與 3–5 個 Wireframe

約 3 小時個人Figma

Step 1 · 把第一條流程補完整

課堂上因為時間關係一定有漏。把六種例外路徑一條不漏全部補上，每一條都要有對應的終點或回到主流程的路徑。

檢查方式：從起點開始，每走到一個菱形就問「另一條路呢」。走完之後，圖上不應該有任何斷掉的箭頭——每條線都要指到某個節點或終點。

Step 2 · Wireframe 補到 3–5 個

  • 課堂上畫了 3 個，補到 5 個以內。第 2、3 張的骨架補上 Auto Layout。
  • 整組至少要涵蓋一個關鍵的例外狀態——空狀態或錯誤狀態擇一，可以是同一張的另一個 Frame。不用每張都做。
  • 只有一小塊變動的畫面，只畫變動的那一塊就好。
  • 每張旁邊寫下六題檢查清單的答案，用 Figma 的文字或註解都可以。

Step 3 · 行有餘力：第二條 Flow（加分項）

作業 5 的交件規格是 1 張 Flow，所以這一步不是必要的。時間夠再做：

  • 選一條會跟第一條交會的路徑，例如登入、搜尋、結帳。
  • 交會的地方要畫出來：使用者在第一條流程走到一半被丟到第二條，完成之後回得到原本的位置嗎？
  • 這是最常出包的地方——很多產品登入完就把你丟回首頁，剛剛在看的東西不見了。

Step 4 · Auto Layout 壓力測試

交件前一定要做這一步，這是最快找出爆版問題的方法。

  1. 把主要容器的 Frame 寬度拉寬 1.5 倍，看有沒有東西沒跟著長、或間距爆開。
  2. 再縮到 0.7 倍，看有沒有文字被截斷、元素重疊。
  3. 把某個標題改成兩倍長的文字，看容器有沒有自己撐開。
  4. 有問題的地方修好，改回原本尺寸再交。

可以用 AI 幫忙的部分

AI 適合幫你檢查有沒有漏，不適合幫你決定流程長什麼樣——它不知道你的使用者是誰。三段提示詞放在講義：檢查流程缺口、從流程推出需要哪些畫面、檢查 Wireframe 的資訊層級。全部都要先貼上你自己畫的東西再問。

使用界線：不要讓 AI 直接生成流程圖或 Wireframe。它不知道你前四個單元做的研究，產出的會是「一般電商大概長這樣」的通用版本，跟你的 Persona 完全脫鉤，評圖時一問就露餡。
